⚙️ Choix technologique
🗄 JSON embarqué → PostgreSQL (production)
Les Work Orders sont des données tabulaires structurées avec des relations claires (MSN → WO via clé étrangère). Une base relationnelle SQL (PostgreSQL) est le choix optimal : requêtes JOIN, index sur MSN, et intégration native avec le pipeline Python XGBoost.

Pourquoi pas NoSQL ? Les données ne sont pas des documents hétérogènes — chaque WO a exactement le même schéma. SQL est plus adapté.
Pourquoi pas CSV seul ? Pas de requêtes, pas de jointures, pas d'index. Performance insuffisante à l'échelle.
Démo offline : la base est embarquée en JSON dans ce fichier HTML.
🧠 Pipeline IA — Flux de traitement
PostgreSQL → SELECT commentaire
→ CamemBERT NER (CPU, ONNX)
→ Entités : defaut, localisation, gravite
→ UPDATE work_order SET nlp_*=…
→ Feature matrix → XGBoost
→ risk_score [0–1] → Dashboard
